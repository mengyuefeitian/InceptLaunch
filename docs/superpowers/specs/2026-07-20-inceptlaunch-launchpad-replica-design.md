# InceptLaunch Launchpad 复刻产品设计

日期：2026-07-20  
项目：InceptLaunch  
目标平台：macOS 26 Tahoe 起  
阶段：产品与体验规格，不含实现计划

## 1. 背景与目标

macOS 26 Tahoe 移除了原有 Launchpad，改为更接近 Spotlight / App Library 的 Apps 入口。新入口更强调搜索、分类和列表效率，但削弱了 Launchpad 用户依赖的空间记忆、自由整理、文件夹和全屏视觉启动体验。

InceptLaunch 的目标是复刻一个完整、稳定、接近系统体验的 Launchpad 替代品。它不是另一个 Spotlight、Raycast 或 Alfred，而是一个以视觉网格、手动布局和瞬时启动为核心的应用启动层。

产品成功标准：

- 用户可以通过熟悉的全屏网格找到并启动应用。
- 用户可以像旧 Launchpad 一样自由拖拽排序、分页和创建文件夹。
- 用户的布局长期稳定，不会因为应用扫描或系统更新被随意打乱。
- 应用唤起、搜索、退出和启动动作足够快，形成肌肉记忆。
- 在 macOS 多显示器、深浅色模式、键盘操作和权限限制下表现可靠。

## 2. 非目标

InceptLaunch v1 不追求成为通用命令启动器。

明确不作为首版核心目标：

- 文件搜索。
- 网页搜索。
- 脚本执行器。
- 剪贴板历史。
- AI 助手入口。
- 深度自动化平台。
- 完全替代 Spotlight、Alfred 或 Raycast。

这些能力可以在未来作为扩展模块探索，但不能影响 Launchpad 复刻体验的简洁性。

## 3. 用户体验原则

### 3.1 空间记忆优先

Launchpad 的价值不只是“能找到应用”，而是“我知道图标在第几页、哪个位置”。InceptLaunch 必须保护用户布局，避免自动排序覆盖手动布局。

### 3.2 视觉启动优先

默认体验应是全屏或近全屏 overlay，显示大图标网格、分页和文件夹。搜索是辅助路径，不是唯一入口。

### 3.3 macOS 原生感

界面需要符合 macOS 桌面习惯：

- 支持键盘、鼠标、触控板。
- 使用系统自适应颜色、材质和动态效果。
- 尊重深色/浅色模式。
- 关键动作有菜单、快捷键或设置入口。
- 不强行占用与系统冲突的快捷键。

### 3.4 稳定胜过炫技

用户对启动器的容错很低。扫描、布局、启动和快捷键必须可靠。动画和高级功能应建立在稳定核心之上。

## 4. 功能分层

### 4.1 P0：基础可用替代品

P0 是“能替代 Launchpad 打开应用”的最低标准。

#### 全屏启动台界面

- 显示全屏或近全屏 overlay。
- 背景使用模糊或半透明材质。
- 使用应用图标网格。
- 显示应用名称。
- 支持多页分页。
- 显示页面指示器。
- 点击空白区域、按 Esc 或再次触发快捷键可关闭。

#### 应用扫描与索引

系统需要发现并维护可启动应用清单。默认扫描范围：

- `/Applications`
- `~/Applications`
- `/System/Applications`
- `/System/Library/CoreServices/Applications`

应用模型至少包含：

- 应用显示名称。
- Bundle ID。
- `.app` 路径。
- 图标。
- 版本号。
- 最近扫描时间。
- 是否仍存在。
- 是否隐藏。

扫描规则：

- 初次启动自动扫描。
- 应用新增、删除或移动后能刷新。
- 扫描不能打乱用户手动布局。
- 已不存在的应用应标记为失效，并在界面中温和处理。

#### 应用启动

- 点击图标启动应用。
- 如果应用已运行，优先切换到该应用。
- 启动成功后关闭 overlay。
- 启动失败时显示明确错误，例如路径不存在、应用损坏或权限不足。

#### 搜索

- 顶部搜索框。
- 输入时实时过滤应用。
- 支持应用名称、Bundle ID 和别名匹配。
- 回车启动当前首选结果。
- 方向键移动选择。
- Esc 清空搜索；搜索为空时 Esc 关闭 overlay。

#### 唤起入口

- 全局快捷键。
- 菜单栏入口。
- Dock 图标入口。
- 设置页中可配置是否开机启动。

默认快捷键不能与 Spotlight、系统截图、Mission Control 等高频系统快捷键冲突。推荐默认值为用户可修改的 `⌥ Space` 或 `⌃⌥L`。

### 4.2 P1：完整 Launchpad 复刻

P1 是“用户会感觉旧 Launchpad 回来了”的标准。

#### 手动排序

- 拖拽图标改变位置。
- 支持跨页拖拽。
- 新应用默认追加到最后一页或用户指定区域。
- 删除或隐藏应用后不重排其他应用的相对顺序。
- 布局持久化。

#### 文件夹

- 将一个应用拖到另一个应用上创建文件夹。
- 文件夹可命名。
- 文件夹内显示小网格。
- 支持文件夹内排序。
- 支持从文件夹拖出应用。
- 文件夹为空时自动消失。

#### 编辑模式

- 长按、右键菜单或快捷键进入编辑模式。
- 编辑模式中支持拖拽、文件夹管理和隐藏。
- 可选图标抖动动画。
- Esc 或完成按钮退出编辑模式。

#### 卸载与隐藏

卸载是高风险动作，应谨慎设计。

- Mac App Store 应用可显示删除按钮。
- 普通 `.app` 默认提供“移到废纸篓”，不直接永久删除。
- 系统应用和受保护应用不可删除，并说明原因。
- 所有删除动作必须二次确认。
- 提供“隐藏应用”作为更安全、更常用的组织方式。

#### 多显示器与 Space

- 默认在当前鼠标所在显示器或当前活动显示器打开。
- 可设置是否在所有显示器显示。
- 在全屏应用、多个 Space、Stage Manager 场景下尽量保持可预测。
- 关闭后焦点返回之前的应用。

#### 动画体验

- 打开/关闭：淡入、缩放、背景模糊过渡。
- 翻页：平滑滑动。
- 文件夹：展开/收起动画。
- 拖拽：图标让位动画。
- 搜索：结果过滤平滑过渡。

动画必须可关闭或随系统“减少动态效果”设置降低。

#### 键盘导航

- 方向键移动选择。
- 回车启动。
- Tab 在搜索框和网格间切换。
- 字母输入可直接进入搜索。
- Esc 按上下文清空搜索或关闭。

### 4.3 P2：优于原 Launchpad 的增强

P2 是产品差异化，不应阻塞第一版完整复刻。

#### 隐藏与清理

- 隐藏应用。
- 恢复隐藏应用。
- 显示/隐藏系统应用。
- 自动识别 helper、uninstaller、后台组件等低价值条目。
- 支持用户自定义隐藏规则。

#### 智能分组

- 按类别分组。
- 按最近使用排序。
- 按安装时间排序。
- 按使用频率排序。

这些能力必须作为可选视图，不得覆盖用户手动布局。

#### 多套布局

- 工作布局。
- 娱乐布局。
- 演示布局。
- 极简布局。

用户可在不同布局之间切换。每套布局独立保存页面、文件夹和隐藏规则。

#### 旧 Launchpad 布局迁移

如果系统仍保留可读数据，可提供实验性迁移：

- 读取旧 Launchpad 数据库。
- 迁移页面顺序。
- 迁移文件夹。
- 迁移应用位置。

该能力受系统版本和权限限制影响，不能作为首版核心承诺。

## 5. 信息架构

### 5.1 主界面

主界面由以下区域组成：

- 搜索框。
- 应用/文件夹网格。
- 页面指示器。
- 编辑模式控制，例如完成、隐藏、删除。
- 错误或权限提示。

默认状态聚焦在网格。用户开始输入时进入搜索。

### 5.2 设置界面

设置应作为独立 macOS Settings scene，而不是主界面内的普通页面。

设置项：

- 全局快捷键。
- 开机自启动。
- 显示菜单栏图标。
- 显示 Dock 图标。
- 网格行列数。
- 图标大小。
- 是否显示应用名称。
- 背景模糊强度。
- 扫描目录。
- 隐藏应用管理。
- 多显示器行为。
- 重置布局。

### 5.3 菜单栏菜单

菜单栏入口保持简短：

- 打开 InceptLaunch。
- 重新扫描应用。
- 设置。
- 退出。

## 6. 数据模型

### 6.1 AppRecord

表示一个可启动应用：

- `id`：稳定内部 ID。
- `bundleID`：Bundle ID，可为空。
- `name`：显示名称。
- `localizedName`：本地化名称。
- `path`：应用路径。
- `iconCacheKey`：图标缓存键。
- `version`：版本。
- `source`：系统、用户、App Store、外部、自定义。
- `isHidden`：是否隐藏。
- `isMissing`：路径是否失效。
- `lastSeenAt`：最近扫描发现时间。
- `lastLaunchedAt`：最近启动时间。

### 6.2 Layout

表示用户布局：

- `pages`：页面数组。
- `folders`：文件夹数组。
- `looseItems`：未归入文件夹的应用项。
- `hiddenAppIDs`：隐藏应用。
- `gridConfig`：行列数与图标尺寸。

### 6.3 Folder

表示文件夹：

- `id`：稳定 ID。
- `name`：用户命名。
- `items`：内部应用顺序。
- `createdAt`。
- `updatedAt`。

### 6.4 UserPreferences

表示偏好：

- 快捷键。
- 开机自启动。
- 菜单栏/Dock 显示策略。
- 背景与动画设置。
- 扫描目录。
- 多显示器策略。
- 是否显示系统应用。

## 7. 数据流

### 7.1 初次启动

1. 应用启动。
2. 加载用户偏好。
3. 加载已有布局；如果不存在，创建默认布局。
4. 扫描应用目录。
5. 合并扫描结果与布局。
6. 显示引导，提示设置快捷键和基础偏好。

### 7.2 应用扫描

1. 扫描器发现 `.app` bundle。
2. 读取元数据和图标。
3. 生成或匹配稳定 AppRecord。
4. 新应用加入“未放置队列”或默认追加到末尾。
5. 缺失应用标记为 missing。
6. 保存索引。

### 7.3 打开启动台

1. 用户通过快捷键、菜单栏或 Dock 触发。
2. 系统决定显示器和 Space 行为。
3. Overlay 出现。
4. 搜索框和网格进入可交互状态。

### 7.4 启动应用

1. 用户选择应用。
2. 检查路径和可启动性。
3. 如果已运行，激活应用。
4. 否则调用系统启动。
5. 成功后关闭 overlay。
6. 更新最近启动时间。

## 8. 错误处理

### 8.1 应用不存在

显示“此应用已移动或删除”，并提供：

- 重新扫描。
- 从布局中移除。
- 定位原路径。

### 8.2 权限不足

显示需要权限的原因，并引导用户到系统设置或重新尝试。

### 8.3 快捷键冲突

设置快捷键时检测常见冲突。若无法可靠检测系统占用，显示风险提示并允许用户修改。

### 8.4 图标加载失败

使用默认应用图标占位，不阻塞应用显示和启动。

### 8.5 删除失败

删除或移到废纸篓失败时，不改变布局状态，并展示失败原因。

## 9. macOS 实现约束

此设计面向 macOS 原生应用实现。

建议架构：

- SwiftUI 负责主界面、设置和大部分状态绑定。
- AppKit 负责全局快捷键、窗口层级、多显示器 overlay、焦点恢复、应用启动细节和低层拖拽行为中 SwiftUI 不稳定的部分。
- 持久化可先用本地 JSON 或 SQLite；首版建议先使用本地 JSON，等布局/同步需求复杂后再迁移。

需要提前验证：

- 全屏 overlay 是否能可靠覆盖当前显示器。
- 全局快捷键注册方式和沙盒限制。
- 应用扫描在沙盒与非沙盒模式下的可行性。
- Mac App Store 分发是否影响扫描目录、启动其他应用、移到废纸篓等能力。

## 10. 验收标准

### 10.1 P0 验收

- 首次启动能扫描并展示常见应用。
- 用户能通过全局快捷键打开和关闭启动台。
- 用户能搜索应用并回车启动。
- 点击应用能启动或切换到已运行应用。
- 重启 InceptLaunch 后仍保留基础索引和设置。

### 10.2 P1 验收

- 用户能拖拽排序并在重启后保留布局。
- 用户能创建、命名、打开和删除文件夹。
- 用户能隐藏应用并在设置中恢复。
- 编辑模式可用，且不会误删应用。
- 多显示器环境下打开位置可预测。
- 深色/浅色模式下界面可读。

### 10.3 完整复刻验收

- 一个旧 Launchpad 重度用户可以完成日常应用启动、整理和查找，不需要回到系统 Apps 入口。
- 用户可以依靠图标位置形成空间记忆。
- 新装/删除/移动应用不会破坏既有布局。
- 基础操作延迟足够低，主观感受接近系统组件。

## 12. 关键产品取舍

推荐首版坚持“Launchpad 优先”：

- 手动布局优先于智能排序。
- 视觉网格优先于命令输入。
- 隐藏优先于删除。
- 稳定启动优先于丰富动画。
- 本地持久化优先于云同步。

这会让 InceptLaunch 更像一个值得信赖的系统替代组件，而不是一个功能很多但核心体验摇晃的启动器。
